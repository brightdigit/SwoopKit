## 1.0.0-alpha.1

The first release of SwoopKit: the Apple release-data records that SwoopMistKit writes to the Swoop CloudKit public database, SwoopCloudKit reads back, and Bushel and Stewed match installed software against. The records moved here from Bushel's `BushelFoundation`. It's an alpha: the API may still change before 1.0.0, but field names, the `Codable` output and `recordName`s are the persisted format and are meant to stay stable. Add it with `.package(url: "https://github.com/brightdigit/SwoopKit.git", from: "1.0.0-alpha.1")` and the `SwoopKit` product.

* Add the release-record models, moved out of Bushel's `BushelFoundation`: `SDKVersionRecord` (with `Platform`), `SimulatorRuntimeRecord`, `XcodeVersionRecord`, `SwiftVersionRecord`, `RestoreImageRecord` and `DataSourceMetadata`, plus `RestoreImageRecordValidationError` and `DataSourceMetadataValidationError`. Every type is `Sendable`, the records are `Codable`, and each record has a stable CloudKit `recordName` (e.g. `SimulatorRuntime-iOS-24B114`, `XcodeVersion-15C65`, `RestoreImage-<build>`) (brightdigit/Stewed#151) by @leogdion in https://github.com/brightdigit/SwoopKit/pull/1
* Add `SimulatorRuntimeRecord.ReleaseLabel` (`.beta(N)`, `.releaseCandidate(N)`, `.final`): parsed from and encoded as Apple's "Beta 4", "RC 1" or "Final", and `Comparable` (Beta 1 < … < RC 1 < … < Final). `SimulatorRuntimeRecord` also carries the SDK builds the simulator index maps to it (`sdkBuildNumbers`) and an `isPrerelease` derived from the label by @leogdion in https://github.com/brightdigit/SwoopKit/pull/1
* Use typed throws throughout: `RestoreImageRecord.validate()` throws `RestoreImageRecordValidationError` (hash length and hex, file size, `https` download URL) and `DataSourceMetadata.validate(sourceName:recordTypeName:recordCount:fetchDurationSeconds:)` throws `DataSourceMetadataValidationError` by @leogdion in https://github.com/brightdigit/SwoopKit/pull/1
* Foundation is the only dependency. Requires Swift 6.4 (swift-tools-version 6.4, Swift 6 language mode, complete strict concurrency; Xcode 27.2 on Apple platforms) and supports macOS 12, iOS 18, watchOS 11, tvOS 18, visionOS 2 and Mac Catalyst 18, plus Linux, where the whole package builds by @leogdion in https://github.com/brightdigit/SwoopKit/pull/1
* Add a DocC catalog, built by `Scripts/docc.sh` (`make docs`) with warnings as errors; there is deliberately no swift-docc-plugin dependency, so packages that depend on SwoopKit never resolve it (brightdigit/Stewed#160) by @leogdion in https://github.com/brightdigit/SwoopKit/pull/1
* CI (pull requests only): Linux on the `swift:6.4` noble and jammy images, macOS and iOS, watchOS, tvOS and visionOS simulators on Xcode 27.2, the DocC build, swift-format and SwiftLint, and an `unsafeFlags` check of the package manifest. CodeQL is removed until it supports Swift 6.4 by @leogdion in https://github.com/brightdigit/SwoopKit/pull/1
* Add the Claude Code GitHub workflow by @leogdion in https://github.com/brightdigit/SwoopKit/pull/2
* Known limitation: decoding doesn't validate. Call `RestoreImageRecord.validate()` (or `isValid`) and `DataSourceMetadata.validate(…)` after ingesting external data. `DataSourceMetadata`'s initializer checks the same rules with `precondition`, so invalid input traps rather than throws
* Known limitation: Mac Catalyst is declared in `Package.swift` but has no CI lane
* Known limitation: `XcodeVersionRecord.sdkVersions` is a JSON string (e.g. `{"macOS": "14.2", "iOS": "17.2"}`), and `minimumMacOS` and `includedSwiftVersion` hold record names rather than typed references
